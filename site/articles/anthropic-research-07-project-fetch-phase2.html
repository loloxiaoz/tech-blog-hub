中文摘要
Project Fetch 第二阶段：不借助人类操作，Claude Opus 4.7 在所有人类团队完成过的任务上至少快 10 倍，四项共同任务平均快 18.9 倍；但精确「取球」这项闭环控制仍是短板。

回顾第一阶段

2025 年 8 月，Anthropic 做了一次实验：让并非机器人专家的 Anthropic 员工，用现成的四足机器人（下称 robodog）完成一些复杂且有趣的任务。实验叫 Project Fetch。

结果是：能使用当时最先进模型（Claude Opus 4.1）的队伍明显胜过只能靠互联网与自身聪明才智的队伍。有 Claude 的队伍做得更多、更快。

在把同事拖去仓库之前，Anthropic 先确认了 Opus 4.1 能否完全独立完成这些任务。答案明确：不能。和没有 Claude 的人类队伍一样，它卡在「如何连接机器人」这个前置任务上。

但 AI 模型进步很快——比当年差点撞上人类队伍的失控 robodog 还快。

于是 Anthropic 决定重做 Project Fetch，看新一代模型能否超过上一代。结果不仅超过了：Claude Opus 4.7 在没有任何人类协助的情况下，在所有参与者不到一年前完成过的任务上，比最快的人类队伍快约 20 倍。

这并不意味着大语言模型已经解决了机器人学，远非如此。最新的 Claude 模型仍然难以用机器人精确移动沙滩球——也就是 Project Fetch 里「取物」的部分。这些实验也没有涉及更困难的底层机器人控制，例如开发特定的驱动策略。

但模式再次出现：先是模型帮助人类，然后人类帮助模型，最后模型基本能自己做。我们在网络安全领域见过这一幕，现在同样的动态开始在 AI 与物理世界的交汇处成形。

第二阶段做了什么

原始 Project Fetch 中，Anthropic 员工被随机分配为「有 Claude」与「无 Claude」两队，依次完成：用厂商手柄操作 robodog、连接视频与激光雷达传感器、写程序手动控制 robodog、开发路径监控、写程序检测沙滩球，最后整合起来自主取球。

这次自主化更新中，无法让 Claude 使用物理手柄，也没有评估研究者用 Claude 编写的控制器取球所需的时间（但确认了它能按预期工作）。

在剩余任务子集上，Opus 4.7 在 Claude Code 中以 adaptive thinking、effort 设为最大运行三次。记录每个目标的耗时，并定性评估成功程度。

研究者的角色仅限于：把运行 Claude Code 的笔记本插到 robodog 上、输入初始提示、批准命令、批准模型进入下一任务。

Claude 在哪里表现出色

简单说：在 2025 年 8 月至少被一支人类队伍完成的每一项任务上，Opus 4.7 都至少快 10 倍。

如果只看两支人类队伍都完成的四项任务：Opus 4.7 平均比无 Claude 队伍快 37 倍以上，比有 Claude 队伍快 18 倍以上。

人类在多种连接传感器的方法之间犹豫时，Opus 4.7 能迅速找到最佳路径。它写的大部分代码第一次就有效——这在原始实验的两支人类队伍中都没有发生。代码量也说明了效率：它和两支人类队伍一样成功甚至更成功，但产出的代码比有 Claude 的队伍少近 10 倍。

Opus 4.7 并不完美。例如它默认使用了一个过时的目标检测算法。但即便这样，它也能绕过问题，得到有效解法。

在模型能力范围内，任务完成时间的组内方差很小。总体而言，对这次实验中处于其能力范围内的任务，Claude 已经相当可靠。

值得强调：这些进步并不是专门提升模型机器人能力的结果。和 LLM 发展史上的许多进步一样，它们来自更通用的规模扩展。

Claude 在哪里吃力

人类用双手、经过一些练习，可以把 robodog 轻轻把沙滩球推回起点（一块假草坪）。这需要快速感知球是否偏离、这个误差与上一条指令的关系、球现在在哪，然后调整后续输入更精确地移动球。这是人类擅长的闭环——至少在犯一些错并从中学习之后。

第二阶段中，Claude 难以捕捉这种微妙之处。和走到「写自主取球程序」阶段的人类一样，Claude 能把机器人移到球后、摆好位置准备把球撞回起点；但控制很差，也没有成功。

一位比第一阶段志愿者更有机器人经验的研究者，成功完成了自主取球的编程。给足时间与额外脚手架，当前这一代 Claude 很可能也能做到。接下来要观察的，是模型能否以它在 Project Fetch 其他环节展现出的速度与可靠性，完成这个最后的任务。

这意味着什么

在第一阶段的文章里，Anthropic 强调 LLM 能为需要使用机器人的非专家提供助力。现在这一点比之前更成立：模型可以更快地独自完成过去需要人机结对编程的工作，人们因此能更快转向控制和使用机器人。对某些任务，人类在回路中操控机器人，可能仍然强过「虚拟手指放在方向键上」的 AI。

真正有趣且不同的是：我们似乎更接近一个模型能相对容易地使用现成物理工具的世界——至少对有限目的而言。这类似 AI 模型在转向 agentic 编程时，学会使用 string-replace 这类现有软件编辑工具。

我们可能正进入物理 agentic AI 的早期时代。

还需要更多研究来理解模型能否让这些物理工具更定制化：为特定任务编写控制策略，或设计机器人系统。通往「具备物理能力且可适应的语言模型」这一更通用愿景，可能仍有实质性障碍。但我们已经看到，看似很大的能力距离可以被快速跨越。模型构建自己的软件工具，不久前还显得荒诞，如今正在发生。认为硬件领域不会走上同样轨迹，并不明智。
