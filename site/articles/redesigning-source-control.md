# Redesigning source control at Anthropic（重新设计版本控制）

## 背景：瓶颈从写代码转移到开发者基础设施

在 Anthropic，写代码已不再是构建系统或做研究的瓶颈——Claude 能自主迭代研究循环、微优化复杂程序、从零搭建新服务。真正的瓶颈变成了为「人类规模」设计的开发者基础设施：版本控制、构建与 CI。

数据很直观：2026 年 5 月，Anthropic 单仓日均合并约 2,500 次代码变更；到 9 月，日均超过 30,000 次。团队认为合并代码的潜在需求近乎无限，每消除一个瓶颈，代码产出就会立刻再上一个台阶。

主分支历史接近 100 GB，压缩后的工作副本超过 25 GB；每天约 2,500 万次代码检出（还不含开发者环境、Agent 沙箱与研究任务），若用 git 直接拉取，每天将产生超过 600 PB 流量。团队一度运行数百个内部 git 镜像，但仓库增长后镜像的磁盘与内存都成了上限，种子快照也迅速落后于 main。

关键的洞察是：git 是为「分布式、离线」设计的，每个克隆都是完整仓库；而 Anthropic 的客户端几乎全是永远在线的 Agent 和任务。让 git 优秀的那些特性，恰恰在拖累规模化。

## 面向 Agent 规模的版本控制五原则

1. **客户端永远在线**：不再假设离线可用，客户端按需向始终可达的服务器取数据。
2. **客户端/服务器不对称**：服务器负责文件历史、blame、创建提交、合并与 rebase；客户端只维护有界本地缓存、铺开工作副本、监控文件变化。
3. **版本控制即服务**：所有 source control 查询都暴露为 API，CI 任务甚至不需要本地仓库，自动 bisect、revert 流水线才可行。
4. **一切水平可扩展**：数据分布存储，任何地方都没有完整仓库副本，也没有 packfile，因而无需仓库维护。
5. **提交必须廉价、增量、无锁**：提交/rebase/merge 都在服务端完成；成本随变更大小而非仓库大小增长；除 main 与发布分支外尽量不用 ref。

此外，工作副本是可选的、天生稀疏的：读写工作负载都可以完全通过 API 完成，只有确实需要落盘时才按需物化。

## Scion 的设计

### 数据单元：changeset

Scion 的工作单元是「changeset」，本质是预写日志中的一条记录。它不像 git commit 那样存树指针，而是存相对第一个父提交的变更文件列表，以及指向 blob 存储中压缩文件内容的、按内容寻址的指针。changeset 在服务端创建、即时全局可见。

由于没有 packfile、没有锁、没有跨服务器协调、没有 ref 需要挪动，接收 changeset 的吞吐可以非常高。

### 派生数据

changeset 只记录变化，无法直接回答「谁最后改了某行」「哪些提交影响了某文件」。Scion 从 changeset 构建派生数据（blame、路径历史、提交图的跳表等），每种都递归定义，并通过统一机制计算。好处是：新增一种派生数据很容易；可按需选择即时计算或延迟计算；客户端看不到内部结构，因此可以自由优化。

### 分层缓存架构

Scion 服务器集群提供版本控制 API，所有数据按内容寻址且不可变，任何服务器都能缓存而无需彼此协调。客户端通过 `scion-daemon` 与节点级缓存交互，区域缓存 `scion-cache` 直接从内存按磁盘格式流式返回对象，缺失时再向权威 `scion-servers` 请求。三层响应相同的 RPC，客户端无需感知缓存拓扑，但严格分层以隔离故障域。

每一层缓存命中率都超过 99%，且不需要长期状态，扩容容易。最终 Scion 基础设施在 CPU 与内存上的占用比过去的 git 镜像方案小 200 倍；CI 与研究任务检出代码快了两个数量级（秒级而非分钟级），仅 CI 就回收了 25% 的 CPU 容量。

## 经验教训

- **小团队快速开发会成为常态**：7 个人在五个月内构建了 Scion、代码评审工具 Antique 以及另外半打相关系统，并完成全量迁移；同期日均合并量增长了 10 倍。
- **工程师的价值转向判断与取舍**：参与该系统的工程师都承认 Claude 写代码比自己强，但他们仍提供对跨系统组件与设计权衡的理解。工程师的一项重要工作是对 Claude 说「不」——阻止它为迎合某个模式而违反核心约束，或为假想风险过度设计。
- **质量与优化显著提升**：Claude 能比人更快地写大量代码，Scion 因此成为团队测试最充分、防御最完备的代码库之一，甚至顺手发现了需要专家数天才能找到的祖先查询算法优化。
- **新的运维方式**：团队用 Claude 监控单个组件健康度，创造了「superfans」——专盯某一个组件的 Claude，能发现传统告警捕捉不到的细微异常。
- **重新审视人类规模的流程**：在 Agent 规模下，合并队列与「测试运行时全局锁」都不再合理，团队转向合并后与部署前的自动化测试，冲突交给 Claude 修复。
