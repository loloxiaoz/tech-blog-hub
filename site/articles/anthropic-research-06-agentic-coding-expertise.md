# Agentic Coding and Persistent Returns to Expertise（智能体编程中专业知识的持续回报）

## 核心发现

- 基于 2025 年 10 月至 2026 年 4 月约 40 万次交互式会话、约 23.5 万人的隐私保护分析，提出一个研究交互式 agentic 编程的框架：任务构成、人机协作、成功率
- 典型会话中，人做大部分规划决策（做什么），Claude 做大部分执行决策（怎么做）。人的领域专业知识越强，Claude 每条指令做的工作越多。在编码任务上，各主要职业的成功率平均与软件工程师几乎相同
- 专业知识越强，会话越常以成功收尾——但「中级」与「专家」之间差距不大。七个月内，调试类会话占比下降近一半，使用转向更端到端的 agent 模式：部署与运行代码、分析数据、写非代码文档
- 同期，典型任务的价值（通过与自由职业招聘信息对比估算）在几乎所有工作类型中上升，平均约 25%

## 引言

agentic 编程已经起飞。自 2025 年底以来，有编码 agent 活动的 GitHub 项目占比翻了一倍多；Claude Code 用户平均每周使用 20 小时。

没有正式编程经验的人，能否成功指挥 agent 完成复杂技术工作？这些工具的快速普及与进步，对更广泛的知识工作意味着什么？

本报告基于约 40 万次会话、约 23.5 万人的隐私保护分析，给出 Claude Code 在实践中的使用证据。它延续了此前关于会话自主性、以及 Claude Code 如何改变 Anthropic 内部工作的研究，提出一个描述交互式编程助手使用的框架：做什么工作、谁在做、是否成功。

Claude Code 上发生的事，可能是知识工作走向的预演。Claude 正在处理更复杂、更有价值的任务；同时，agentic 编程仍存在清晰的分工：人决定构建什么，agent 决定如何构建。

我们也看到证据表明，放大工具有效性的是领域专业知识，而不是编程熟练度。领域专家成功率更高，也更容易从错误与误解中恢复。但专家与中级之间的差距不大——说明对一个领域「够熟练」，就足以几乎同样有效地使用工具。

## 分工

### 人们用 Claude Code 做什么

把每次会话归入九种工作模式之一：

- 直接写或维护代码：构建新东西（25%）、修复坏掉的东西（26%）、测试与编排其他 agent 或自动化管线（5%）
- 运维软件：部署、配置、运行管线、监控系统（17%）
- 弄清要做什么：理解现有系统如何运作、在动手前做规划（14%）
- 与代码无关或代码只是附带：数据分析、通过演示与其他文字文档沟通（13%）

约 56% 的会话是写代码、修代码、测试与编排。

### 谁决定什么

能力评测显示天花板很高且在上升：在 METR 的时间跨度评测等基准上，前沿模型已经能自主完成人类需要数小时的软件任务，并在过程中绕过障碍。

从两个角度看自主性：人把多少决策托付给 Claude，以及给 Claude 多少动作。

平均而言，人做约 70% 的规划决策，只做 20% 的执行决策。实践中分工清晰：人决定做什么，agent 决定怎么做。

典型会话约 4 轮。每次提示平均触发约 10 个 Claude 动作，有时超过 100 个。每轮中，Claude 读文件、改代码、跑命令，并平均写出 2,400 词输出。

### 专业水平

Claude 从每段对话记录中给用户在该任务上的专业度打 5 分制评分（新手到专家）。分类器看三个信号：用户表述指令的精确度、要求 Claude 验证什么、以及通常是用户纠正 Claude 还是 Claude 纠正用户。

关键在于，专业度是任务特定的。资深工程师第一次问 Rust 问题，在 Rust 上是新手；从未用过 Python 的会计，如果能准确告诉 Claude 一个 Python 脚本必须执行哪些对账规则，并抓住它在月末结账时处理错的边界情况，那他在这个任务上就是专家。

- 新手会话：每次提示约 5 个 Claude 动作、约 600 词输出
- 专家会话：12 个动作、3,200 词输出，动作链长度是新手的两倍多，输出是五倍

这种差距出现在每一种工作类型与每一个任务价值区间。控制工作模式、任务价值、月份、职业与模型家族后，每提升一级专业度仍增加 9% 的动作与 13% 的输出（p < 0.001）。

## 谁在使用，用来做什么

从会话记录推断用户职业，映射到美国劳工统计局 SOC 分类的 23 个大类。分类器只看项目上下文、文件名称与结构、引用的产物、使用的词汇，并被明确要求不得把「写代码」本身当作「编程职业」的证据。

约 70% 的会话能推断出职业。最大群体是计算机与数学职业，其次是商业与金融、艺术设计与媒体、管理、生命物理与社会科学。增长最快的非软件职业群体是管理、销售与法律。

2025 年 10 月到 2026 年 4 月，工作构成变化明显：

- 修复坏代码的会话占比从 33% 降到 19%
- 运维软件从 14% 升到 21%
- 写作与数据分析从约 10% 翻倍到 20%
- 平均会话的估算价值上升 27%；构建、运维、修复类任务分别增长约 43%、34%、32%

## 成功取决于用户带来什么

用两种互补的、基于对话记录的指标：

- **判定成功**：分类器读完整个记录，判断用户是否做成了想做的事
- **验证成功**：既被判定成功，又至少有一个硬性可验证信号——匹配工作的 git commit、通过的测试套件、或用户的明确肯定

### 专业度的回报

- 新手会话：15% 验证成功、77% 至少部分成功
- 中级及以上：28% 到 33% 验证成功、91% 到 92% 部分成功
- 遇到麻烦的会话里，验证成功比例从新手的 4% 升到专家的 15%
- 会话挣扎时，19% 的新手会话最终被放弃，其他人为 5% 到 7%

大部分收益来自「新手到中级」；中级到专家，斜率下降。

### 职业可能没有专业度重要

软件相关职业整体验证成功约 30%，其他职业约 26%。在产出代码的会话中，数据集中最大的十个职业全部落在软件工程师成功率上下 7 个百分点以内。管理类职业最高，略高于软件工程。

## 展望

agentic 编程在放大某些知识与技能，同时替代另一些。在产出代码的会话中，每个主要职业的成功率都与软件相关职业相差几个百分点。看来，编码 agent 正在让「编程背景」对成功编程变得不那么重要。

与此同时，成功的会话更常体现领域专业知识。评为专家的会话，验证成功率是新手的两倍多。把 Claude 引向成功的能力，更多来自对领域的掌握，而不是写代码的能力。而且收益主要来自「胜任」而非「精通」——对领域有可用的理解就能拿到大部分好处，深度专业化只在此基础上再加一点。

如果专业度的回报开始下降，说明模型正在接管目前由用户提供的关键判断力，工具的好处正在向领域专家之外扩散。如果非软件职业用户成功完成编码会话的比例继续上升，可能意味着软件生产正在成为每个领域的日常工作的一部分。
