# The components of agent memory（Agent 记忆系统的组成）

## 核心观点

**Agent 记忆的定义有严格边界。** 文中把「agent memory」限定为 Claude 从经验中获得、并在会话之间保留下来、以可再次读取的上下文形式保存的知识。它不包括其他学习或上下文管理方式：模型权重变化、单次会话内的上下文学习（in-context learning），以及压缩（compaction，用摘要替换较早的对话轮次）。

**记忆本质上是关于「未来需要什么」的预测。** 写下一段规则，就是在预测这个模式以后还会用到；记下一个已验证的事实，就是预测未来会话可以直接依赖它而无需再核对。模型越强，这种预测做得越好。

**小记忆优于大记忆。** 在 Pokémon 评测中，Sonnet 3.7 不加区分地记录了 413 个文件、225 个文件夹，只拿到 1 枚徽章；Fable 5 只写 9 个文件、2 个文件夹加一个 global.md，却拿到 4 枚徽章。原因是游戏的状态每回合都在变，冗余记录迅速过期，Claude 反而要花越来越多时间翻自己的记忆，而不是玩游戏。

## 关键机制

### 记忆笔记（memory notes）

Claude 可以在会话过程中标记重要事件，或把它们写入记忆目录中的笔记，方便以后检索。类比人脑：体验发生时释放的化学信号会「标记」重要记忆，这些被标记的记忆在离线时被更频繁地重放（replay），从而巩固为长期记忆。

### Dreaming：在空闲时整理记忆

借鉴 Letta 与 UC Berkeley 提出的 sleep-time compute，Agent 可以利用交互之间的空闲时间回看日志、修正错误、生成笔记与新的记忆表征。这个过程被称为 dreaming。它能做四件事：

1. **纠错**：把记忆笔记与原始会话记录比对，发现并改写错误。
2. **构建新表征**：例如让 Claude 增量维护一套互相链接的 wiki 页面，作为检索记忆的地图。
3. **提升记忆层级**：把关键笔记浮动到记忆层级顶端，由 harness 在每次会话开始时预加载进上下文。
4. **聚焦目标**：让记忆围绕特定目标生长（例如围绕被帮助的用户组织记忆）。

### 记忆分层与预加载

被注入到每次会话上下文的顶层记忆必须保持很小：注入会消耗 token，错误笔记会被带进每一个会话，而且更长的指令文件反而会降低遵循度。因此 dreaming 的一项主要工作就是维持这一层「薄」——把细节下移，只在顶部留下链接索引。Claude Code 的 auto memory 同理，每次只加载 `MEMORY.md` 的前 200 行或 25 KB 作为索引。

## 评测证据

- **CL-Bench 1.0 数据库任务**：Claude 每个问题都在新会话开始，只能从跨会话保留的记忆目录取文件。较早的 Sonnet 4.6 只写出零散、未经验证的猜测；Opus 4.7 会合并成一份参考文档并标注哪些事实已验证；Opus 5 首次形成闭环，多数条目包含规则、规则来源、历史答案以及踩过的坑。
- **给规则 vs 给自由度**：当强制规则为「只记录失败」时，Opus 5 与 Opus 4.7 从记忆中获得的性能提升大幅缩水。对强模型而言，让它自行判断什么重要，比预先设定固定规则更有效。
- **Stainless 语料（约 35 万文件、4.2 亿 token）**：用 dreaming 跨 128 个会话增量构建 wiki，25 个问题的得分从 13% 提升到 48%；同时提供搜索工具时，总分从 54% 提升到 61%，且每题约省下 2 万 token。
- **Harvey LAB 法律简报**：当一条评分标准需要跨多份文档整合信息时，查 wiki 的得分 87%，仅用搜索为 73%；如果单份文档就能找到答案，wiki 没有明显优势。也有反例：wiki 一度膨胀到比原始文件还大，等于没有抽象。

## 关键结论

- 告诉 Claude「记忆是用来做什么的」，但不要规定「怎么用」；对新一代模型，放手让其判断重要性效果更好。
- 记忆的价值取决于精选与抽象，而非记录量；「什么该被记住」本身就是核心能力。
- dreaming 把记忆从被动日志变成可自检、可纠错、可重组的知识系统。
